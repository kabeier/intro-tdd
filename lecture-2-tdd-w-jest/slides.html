A test lives in its own file

  • factorial.js holds the code. factorial.spec.js holds the tests
  • In Python, from example import … just worked
  • In JavaScript, a file shares nothing until you export it

So first: how one JS file uses another.

"Same Red-Green-Refactor as Lecture 1. The new part is JavaScript's import/export."

We use Node's way: module.exports / require. The other way (import/export) comes with React, in a future lecture.

Export it, then require it factorial.js · runner.js

** CODE ALONG, about 5 minutes. ** Students: factorial.js, runner.js.

TYPE THIS, in order

factorial.js · part 1

function factorial(num) {
  let product = 1;

  for (let i = num; i > 0; i--) {
    product = product * i;
  }

  return product;
}

runner.js · part 1

console.log(factorial(4));

factorial.js · part 2 (add below, after a blank line)

module.exports = factorial;

In runner.js change console.log(factorial(4)); to const factorial = require("./factorial.js"); console.log(factorial(4));, then save and run.

Ctrl+S, then in the terminal:

node runner.js
  • After steps 1–2, save and run node runner.js: ReferenceError: factorial is not defined. "runner.js has never heard of factorial."
  • Step 3: module.exports = factorial; sends it out. Run again: still the same error. Exporting isn't enough.
  • Step 4: require("./factorial.js") brings it in → 24.
  • The path is relative to this file: ./ = same folder.
  • (The lesson's runner just calls factorial(4);. We wrap it in console.log so you can see the 24.)

How Jest finds your tests

or a folder(any folder)__tests__/
one testdef test_add():test("adds", () => { … })
checkassert x == 4expect(x).toBe(4)
runpytestnpm test

test() takes a description and a function to run later (a callback).

  • test and expect are given to you by Jest. No require needed.
  • Callback: a function you hand to another function, which calls it later.
  • expect(…) wraps the value; .toBe(…) is the matcher: "is it exactly this?"

Group with describe, skip with x factorial.spec.js

** CODE ALONG, about 5 minutes. ** Step 1 is long: copy it from your notes (click the block) or press N. Students can copy it from Code Lab 2.

TYPE THIS, in order

Replace all of factorial.spec.js with (copy it: click the block):

const factorial = require("./factorial.js");

describe("tests factorial for small numbers", () => {
  test("tests factorial(0) = 1", () => {
    expect(factorial(0)).toBe(1);
  });

  test("tests factorial(3) = 6", () => {
    expect(factorial(3)).toBe(6);
  });
});

describe("tests factorial for large numbers", () => {
  test("tests factorial(10) = 3628800", () => {
    expect(factorial(10)).toBe(3628800);
  });

  test("tests factorial(20) = 2432902008176640000", () => {
    expect(factorial(20)).toBe(2432902008176640000);
  });
});

In factorial.spec.js change test("tests factorial(3) = 6" to xtest("tests factorial(3) = 6", then save and run.

In factorial.spec.js change describe("tests factorial for large numbers" to xdescribe("tests factorial for large numbers", then save and run.

npm test

Jest in a container

Dockerfile (in tdd-jest/)

FROM node:18-alpine

WORKDIR /app

COPY package*.json ./

RUN npm install

RUN npm install --save-dev jest

COPY . .

CMD ["npm", "test"]
  • package.json first, then npm install: dependencies are baked into the image
  • COPY . . brings in your code and tests
  • The container runs the suite once and stops
docker build -t jest-tests .
docker run --rm jest-tests
echo $?

** YOUR DEMO, about 3 minutes. ** The Dockerfile is the curriculum's, word for word.

  • Add a .dockerignore with node_modules first, so COPY . . doesn't copy your laptop's node_modules over the container's.
  • Run: same PASS output as on your laptop. echo $? → 0. Break a test, rebuild, run → 1.
